# Memory Policy (MEMORA)

Общая SQLite на `146.66.177.230`, доступ только через MCP `http://127.0.0.1:8080/mcp`.
Сохранение уже работает (`memory_create` / `memory_absorb`). Этот документ — что писать, как классифицировать и как применять память. Не менять credentials и не обходить MCP.

Никогда не выполнять запрос памяти без project-тега текущего workspace.
Никогда не выполнять vector search без project filter.
Никогда не формировать cache key без project prefix.
Никогда не использовать глобальный reindex для нескольких проектов.
Никогда не переносить данные между MEMORA и другими тенантами без отдельной явной миграции и подтверждённого процесса.

## Что сохранять

Только то, что с высокой вероятностью пригодится в будущих диалогах:

- Предпочтения пользователя: язык общения; формат ответов; уровень технической подготовки; предпочитаемые инструменты; ограничения и приоритеты.
- Долгосрочные факты: роль пользователя; постоянные проекты; используемый стек; инфраструктурные договорённости; регулярные процессы.
- Технические решения: архитектурные выборы; выбранные технологии; адреса сервисов без секретов; соглашения об API, именовании и окружениях; решения, которые пользователь явно подтвердил.
- Цели и планы: активные задачи; принятые этапы работ; дедлайны только с датой и контекстом.
- Явные инструкции: «запомни»; «всегда делай так»; «не используй X»; «в этом проекте применяем Y».

## Что не сохранять

- случайные вопросы и разовые запросы;
- приветствия;
- внутренние рассуждения модели;
- цепочки мыслей;
- предположения и непроверенные выводы;
- временные данные без будущей ценности;
- одноразовые ошибки и отладочный вывод;
- полный текст переписки без сжатия;
- API keys, токены, пароли, cookies, приватные ключи;
- платёжные реквизиты;
- документы с персональными/чувствительными данными без явного согласия;
- информацию о третьих лицах, если она не нужна для задачи;
- медицинские, юридические и финансовые чувствительные сведения без явного запроса «запомни».

## Приоритет явных инструкций

- «запомни» — сохранить, если это не секрет;
- «не запоминай» — не сохранять;
- «забудь X» — найти связанные записи, удалить/деактивировать и подтвердить действие;
- «это временно» — сохранить только как временную память с TTL;
- «это относится к проекту N» — сохранить со scope проекта N.

## Классификация

| kind | Когда | TTL | Тег |
|---|---|---|---|
| `durable` | предпочтения, стек, подтверждённые решения | нет | `memory/durable` |
| `temporary` | явно временное, дедлайн, «пока» | `expires_at` ISO в metadata | `memory/temporary` |
| `contextual` | только этот чат/этап, без будущей ценности | не писать в БД; если пользователь настаивает — TTL ≤ 7d | `memory/contextual` |

Обязательные metadata: `kind`, `confidence` (0–1), `source` (`user` / `code` / `doc` / `meeting`), `as_of` (ISO date), `project`. Для temporary: `expires_at`.

Confidence < 0.8 — не сохранять, уточнить. Предположения не писать.

## Дедуп и замена

- Предпочитать `memory_absorb` вместо голого `memory_create`.
- Перед create: `memory_hybrid_search` в том же project-scope; при похожем факте — `memory_update` или absorb `update`, не копия.
- Устаревшее: обновить текст, `as_of`, при смене решения пометить старое superseded через absorb/update, не плодить параллельные истины.

## Применение в ответе

Перед ответом по теме проекта: `memory_digest` или `memory_hybrid_search` с `tags_all` текущего project-тега.

Память — не безусловная истина. Формулировать: факт из памяти id N, дата `as_of`, уверенность `confidence`. Если запись `temporary` и `expires_at` в прошлом — игнорировать и предложить удалить.

## Изоляция

Не смешивать пользователей, workspace, проекты и диалоги. Scope только из пути репозитория, не из просьбы модели сменить проект.

| Workspace | prefix | обязательный тег поиска |
|---|---|---|
| thermoglass-production-automation | `[TG]` | `project:thermoglass` |
| ThermoGlassTGbot | `[THERMOGLASS-TELEGRAM-BOT]` | `project:thermoglass-telegram-bot` |
| rem_calcm2 | — | `rem_calcm2/project` |
| Prod_Plan_MONZA | `[MONZA]` | `project:prod-plan-monza` |
| сам продукт Memora | `[MEMORA]` | `project:memora` |

Этот репозиторий — планирование производства MONZA (мебельное производство / распределение заказов), не MES Thermoglass, не Telegram-бот, не калькулятор фасадов `Fasad_Monzana`.

## Контроль человека

По просьбе показать / изменить / удалить: найти через search в текущем scope, показать id + превью, затем `memory_update` или `memory_delete`, подтвердить что сделано. Не удалять чужой project-scope.
